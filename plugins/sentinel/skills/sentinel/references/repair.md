# 기준 통과까지 수정·재검사

기본 `sentinel` 스킬과 `fix`가 공유하는 절차다. [측정 지침](measurement.md)을 읽고 수행한다. 실행기나 프로젝트 준비가 필요하면 [설치 절차](setup.md)를 따른다. 현재 요청에서 이미 승인한 작업을 다시 묻지 않는다.

1. 요청한 기능 범위와 프로젝트의 CRAP·mutation 기준을 확인한다. 새 설정의 기본값은 CRAP 8 이하·mutation 90% 이상이며 기존 설정값은 유지한다.
2. 요구사항과 관련 테스트를 확인하고 먼저 검사한다. 이미 기준을 통과했다면 결과를 보고한다. `baselineFailed`면 원래 테스트부터 고치고, `qualityFailed`면 점수와 변이 위치를 근거로 코드·테스트를 보강한다. 필요한 정상·경계·오류 입력은 요구사항에서 기대 결과를 확인해 테스트한다.
3. 같은 범위·기준으로 다시 검사한다. 테스트가 올바른 기대 결과를 확인하는지 검토한다. 통과를 위해 기준을 낮추거나 검사 대상을 제외하거나 테스트를 건너뛰거나 검사기를 개조하지 않는다.
4. 중간에 좁은 범위로 확인했더라도 마지막에는 처음 요청한 범위로 다시 검사한다. 요청한 범위에서 `exitCode: 0`, 모든 `results[].status: passed`, 측정된 CRAP·mutation 판정을 확인할 때까지 반복한다. `noChanges`, 미측정, 도구 오류는 통과가 아니다. 파일·함수를 지정한 요청은 그 범위, 전체 통과 요청은 `--all`로 마지막 검사를 한다.
5. 실제 결과와 검사 범위를 보고한다. 사용자의 중단 요청, 실행 권한·외부 의존성 부족, 요구사항 확인이 필요한 문제로 진행할 수 없으면 막힌 원인과 필요한 입력을 알린다. 성공을 보장하거나 실행하지 않은 결과를 통과로 보고하지 않는다.
