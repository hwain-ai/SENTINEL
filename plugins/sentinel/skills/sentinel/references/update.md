# 공식 배포판 갱신 절차

현재 설치된 SENTINEL 중 요청한 구성요소만 갱신한다. 버전 확인과 갱신은 구분하며, `version`에서 이 절차를 자동 실행하지 않는다. 아래 명령은 현재 호스트의 도움말과 설치 범위를 확인한 뒤 사용한다.

## 1. 설치 상태와 갱신 대상 확인

플러그인의 호스트·설치 범위, 실행기 경로·소스 저장소, 프로젝트·도구 경로와 설정을 확인한다. 이전 플러그인·실행기·언어 어댑터 버전을 기록한다. 설치 범위를 모르면 확인한다. `update` 요청은 해당 SENTINEL 구성요소의 갱신 요청이며 같은 동의를 반복해서 묻지 않는다.

## 2. 플러그인 갱신

사용 중인 호스트의 명령만 실행한다. 설치 목록 이름이 실제로 `sentinel`인지 확인하고 해당 목록·플러그인만 갱신한다.

```sh
# Claude Code
claude plugin marketplace update sentinel
claude plugin update sentinel@sentinel
```

```sh
# Codex
codex plugin marketplace upgrade sentinel
codex plugin add sentinel@sentinel
```

사용자·프로젝트 설치 범위는 기존 값을 유지한다. 다른 마켓플레이스 전체 갱신, 플러그인 삭제, 사용자 캐시 직접 편집은 하지 않는다. 새 버전이 설치됐는지 호스트 목록·설치된 manifest로 확인하고, 새 지침을 읽으려면 새 대화나 호스트 재시작이 필요한지 알려 준다.

## 3. 실행기 갱신

확인된 공식 SENTINEL 소스의 원격과 작업 상태를 확인한다. 소스가 깨끗하면 `git pull --ff-only`로 갱신하고 해당 실행기의 가상환경 Python으로 `pip install --upgrade --force-reinstall <확인한 소스 경로>`를 실행한다. 사용자 변경이나 이력 충돌이 있으면 덮어쓰거나 reset하지 말고 충돌을 보고한다. 소스 경로가 확인되지 않는 설치를 임의의 프로젝트에서 갱신하지 않는다.

## 4. 승인된 언어 도구 갱신

갱신한 실행기 패키지의 `admission.json`에서 현재 사용하는 언어의 승인된 최신 `toolVersion`과 `source.repository`, `source.commit`을 확인한다. 버전 문자열을 사전순으로 비교하지 않는다. 원본 도구의 최신 버전을 임의로 설치하지 않는다.

사용하지 않은 새 언어 소스 폴더를 만들고, 각 공식 저장소를 받아 선택한 승인 커밋으로 checkout한다. 저장소 폴더 이름은 `SENTINEL_PY`, `SENTINEL_TS`, `SENTINEL_JAVA`를 유지한다. 기존 소스 폴더의 수정 내용을 삭제하거나 덮어쓰지 않는다.

[설치 절차](setup.md)의 `setup`에 이 새 폴더를 `--sources`로 전달한다. 기존 프로젝트·설정·도구 폴더와 언어·모듈 경로·의존성 옵션을 유지한다. 품질 기준을 새 기본값으로 초기화하지 않는다. 다른 언어까지 설치하지 않는다.

## 5. 확인과 보고

갱신한 실행기의 `--version`, 같은 프로젝트의 `plan`·`version`으로 버전·모듈·승인 상태를 확인한다. 새 도구는 기존 설치 옆에 두고 문제가 있으면 이전 설정과 설치로 돌아갈 수 있도록 유지한다. 완료한 구성요소의 이전/새 버전, 바뀐 경로, 실패·미완료 상태를 구분한다. 별도 요청 없이 기능 코드·테스트 수정이나 품질 검사를 시작하지 않는다.
