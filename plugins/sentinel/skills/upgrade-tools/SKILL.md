# 제작자용 원본 도구 업그레이드

1. 현재 작업이 SENTINEL 제작 저장소인지, 대상 언어와 도구가 무엇인지 확인한다. 일반 사용자 프로젝트에서는 도구나 승인 목록을 바꾸지 않고 `update`를 안내한다. 제작 저장소 위치를 모르면 묻는다.
2. 해당 언어 저장소의 README·잠금 파일·도구 실행 스크립트·CI와 공통 SPEC를 읽는다. 요청한 도구의 공식 릴리스와 호환성을 확인해 대상 버전을 정한다. 전체가 아닌 특정 도구 요청이면 그 범위만 변경한다.
3. 필요한 다운로드 주소·지문·의존성 잠금·어댑터를 함께 갱신한다. 기존 판정 기준을 낮추지 않는다. 출력이나 판정 의미가 바뀌면 SPEC·스키마·기준 사례·실행기도 함께 맞춘다. 바뀐 언어 도구에는 새 어댑터 버전을 부여한다.
4. 해당 저장소 CI에 정의된 설치·오프라인 시험·자체 품질 검사와 응답 계약을 확인한다. 통합 실행기의 `scripts/verify_native.py`는 승인된 버전을 검증하는 도구이므로 후보 버전 검증을 대신했다고 주장하지 않는다. 후보 어댑터는 별도 검증 프로젝트에서 검사하고, 개발용 실험 결과와 정식 승인 결과를 구분한다.
5. 배포·push는 사용자가 요청한 게시 범위 안에서 수행한다. 해당 언어 저장소의 실제 main 커밋과 성공한 CI가 있어야 통합 저장소의 `scripts/admission.py add --language <언어> --commit <커밋>`으로 승인 항목을 추가한다. 승인 근거를 만들거나 검사 실패를 무시하지 않는다.
6. 승인 목록의 lint·verify와 통합 검사를 확인하고 코드·잠금 파일·문서를 함께 갱신한다. 이전/새 버전, 플랫폼별 검증 결과, 호환성 변경, 아직 승인·배포되지 않은 사항을 보고한다.
