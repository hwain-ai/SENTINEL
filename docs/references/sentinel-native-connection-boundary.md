# 언어 도구 설치 연결의 실행·정리 경계

Python·TypeScript·Java를 연결할 때 공통 실행기가 실행과 취소·정리를 책임지고, 언어별 연결부는 검사 도구 호출과 결과 변환을 맡는다.

이 문서는 과거 설계 검토에서 유지할 공통 경계를 정리한다. 현재 설치·검사 방법은 [README](../../README.md), 실제 완료 범위는 [실행 계획](../exec-plans/active/2026-09-sentinel-unified-entry.md)을 따른다.

## 실행과 결과를 구분하는 원칙

설치 확인, 비교 기록 생성, 프로젝트 품질 검사는 서로 다른 성공이다. 종료 코드가 0이더라도 어떤 작업의 성공인지 확인한다. 선택한 프로젝트 대신 고정 예제를 실행해서는 안 되며, 변경 파일이 없어 검사기를 실행하지 않은 결과는 품질 인증의 근거가 아니다.

일반 도구 묶음은 [공통 실행기](../../src/sentinel/protocol.py)가 별도 프로세스 그룹으로 실행한다. 시간 초과·취소·출력 초과 시 그룹을 정리한다. 강제 종료 신호를 받은 자식은 종료 처리 코드를 실행하지 못할 수 있으므로 자식에게만 정리 책임을 맡기지 않는다.

별도 세션의 외부 실행을 추가할 때는 기존 그룹 종료만으로 해당 실행까지 끝났다고 보지 않는다. 생성 완료·소유권·정리 완료를 함께 확인하고, 사용자가 취소한 뒤 다음 모듈이 시작되지 않는지도 시험한다. 이 문서는 실제 누수나 공격 성공을 새로 재현한 기록은 아니다.

## 검토한 책임 배치

|방식|장점|필요한 검증|
|---|---|---|
|부모 SENTINEL이 생성·실행·정리를 소유|연결 프로그램 종료 뒤에도 정리 주체가 남는다.|입력·시간 예산·결과와 소유권을 함께 연결한다.|
|자식 실행 후 부모에게 정리 책임 인계|기존 요청·응답 구조를 유지하기 쉽다.|인계 전후 중단과 진행 중 생성 작업까지 처리해야 한다.|
|별도 관리 프로그램이 감시|검사 명령과 독립적으로 정리할 수 있다.|상주 프로그램 설치·갱신·장애 복구가 추가된다.|

기존 결정은 부모가 책임을 소유하는 방식이다. 별도 상주 관리 프로그램을 추가하지 않는다. 일반 도구 요청·응답 계약을 조용히 바꾸거나 SDK 전체를 작은 도구 묶음에 넣지 않는다.

## 다음 실행에서 확인할 것

1. 성공·품질 실패·도구 오류·취소를 구분하고 미검사를 통과로 올리지 않는다.
2. 취소·시간 초과 뒤 소유한 자식이 남지 않고 다음 모듈이 시작되지 않는지 확인한다.
3. 선택 프로젝트의 원본 보존과 다음 검사 재실행을 확인한다.
4. Codex·Claude가 같은 CLI와 결과 의미를 사용하는지 실제 호출로 확인한다.

6개월 뒤에도 언어 도구 변경은 해당 버전·의존성·호환성 시험에 한정한다. 새 연결이 실패하면 기존 설치와 실행 경로를 유지한다. 프로세스 그룹 정리만으로 파일·네트워크 격리나 부모 자체의 강제 종료 복구를 보장하지 않는다.
