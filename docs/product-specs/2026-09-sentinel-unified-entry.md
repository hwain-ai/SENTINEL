# SENTINEL 통합 명령과 선택형 언어 검사기

결론: 사용자는 하나의 명령으로 설정된 프로젝트를 검사하고, 언어별 검사기는 필요한 것만 독립 설치·갱신한다.

## 승인 근거와 기존 요구사항의 관계

사용자가 2026-09-08에 “3번으로 확정하고 진행해”라고 승인했다. 선택지는 언어별 완전 분리, 전체 도구 일괄 배포, 통합 명령과 선택형 검사기였다. 세 번째 방식이 확정됐다. 기존 요구사항 번호와 각 구성요소의 책임을 유지하면서 `SENTINEL` 통합 실행기를 추가한다. 현재 공개 지원 범위는 Python·TypeScript·Java와 공통 계약·통합 실행기다. 원격 저장소 생성·공개 배포·기존 backend 기본값 전환은 이 승인의 자동 결과가 아니다.

## 단계별 완료의 의미

현재 통합 실행기는 `setup`으로 선택한 언어의 저장소·고정 SDK·묶음을 준비한다. `install` 자체는 지정한 로컬 묶음과 SHA-256만 검증·복사한다. 새 다중 언어 설정은 `--module-root`로 서로 겹치지 않는 폴더를 명시하며, 기존 모듈 설정과 기준값은 보존한다.

2026-09-13에 승인 기준을 운영 격리와 분리해 CI 기반으로 확정했다. 기본 check는 CI를 통과한 어댑터 버전·지문만 실행한다. `certified=true`는 선택한 모든 모듈이 승인된 도구로 실제 검사되어 passed인 경우만 뜻한다. `noChanges`는 정상 종료하더라도 미검사이며 인증하지 않는다. 부분 선택을 저장소 전체 품질 인증으로 해석하지 않는다. experimental은 미승인 실행이고 항상 certified=false다.

단위 시험·설치 상태·스킬 발견·실제 호스트 명령 호출·실제 언어 품질 검사는 각각 증거를 구분한다. Linux에서 통합 설치를 지원하며 Windows는 WSL을 사용한다. macOS의 통합 설치는 현재 미지원이다. CI 통과나 프로세스 정리는 악성 코드에 대한 보안 격리를 보장하지 않는다. 실제 관측과 남은 항목은 [호스트·WSL 검증 기록](../references/sentinel-host-validation.md)에 둔다.
