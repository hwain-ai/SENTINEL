# 문서 관리

사용법과 현재 동작은 공개 문서에 기록한다. 개인 작업 일지, 검증 로그, 비교 조사와 배포 계획은 저장소 밖에 보관한다. 라이선스·제3자 고지와 실행에 사용하는 계약·스키마는 유지한다.

README에는 사용자의 설치·검사 요청과 에이전트의 실행 명령을 나눠 적는다. 명령·설치·판정 코드를 바꾸면 `readme-usage` 규칙에 따라 README의 프롬프트·JSON 예시·상태 설명도 갱신한다. 자세한 옵션은 참고 문서에 두고 README에서는 필요한 위치로 연결한다.

## 수정할 문서 찾기

[문서 색인](index.md)은 각 문서의 요약과 연결된 코드 경로를 보여준다. 연결표의 원본은 [manifest.json](manifest.json)이다. 결과 필드·출력 형식은 `docs/results.md`의 JSON 조각과 설명을 함께 수정한다. `documents`는 문서 경로와 요약, `rules`는 변경 소스 패턴과 확인할 문서를 지정한다. 경로는 저장소 루트 기준이고 `*`는 한 경로 구간, `**`는 하위 경로 전체와 일치한다.

저장소 루트에서 다음 명령을 실행한다. Linux에서는 `python3`, Windows에서는 `py -3`를 사용한다.

```sh
# 현재 커밋 이후 작업트리·스테이징·새 파일의 변경을 검사한다.
python3 scripts/docs_lint.py --base HEAD
# 브랜치 전체 변경을 확인한다. origin/main은 비교할 기준 브랜치다.
python3 scripts/docs_lint.py --base origin/main
```

검사기는 변경된 코드와 그에 연결된 문서 경로를 출력한다. 해당 동작을 확인하고 설명·옵션·예시·제한을 수정한 뒤 다시 실행한다. 소스가 한 규칙에 해당하면 그 규칙에 연결된 문서 중 하나 이상의 본문이 함께 바뀌어야 한다. 여러 규칙에 해당하면 각 규칙을 충족해야 한다. 색인만 재생성하거나 공백만 바꾼 것은 문서 갱신으로 인정하지 않는다.

문서를 추가·이동·삭제하면 `manifest.json`의 경로·요약·연결 규칙도 고친다. 새 기능을 기존 패턴이 포함하지 못하면 규칙을 추가한다. 제3자 문서는 `ignoreDocuments`에 지정한 경로로만 제외한다.

```sh
# 연결표에서 색인을 재생성한다.
python3 scripts/docs_lint.py --write-index
# 문서 등재, 파일 존재, 로컬 링크와 색인 일치를 검사한다.
python3 scripts/docs_lint.py --check
```

검사기는 문서 본문의 의미가 코드와 일치하는지 판단하지 않는다. 갱신 누락과 깨진 파일 링크를 찾는 검사다. 링크의 웹 접속 상태와 문서 안의 제목 앵커도 검사하지 않는다. 코드 주석만 바뀌는 등 사용자 동작이 같을 때도 연결 규칙이 적용되므로, 관련 문서에 그 코드의 설명이 여전히 맞는지 확인하고 필요한 설명을 반영한다.

## push 전에 검사하기

Git 훅은 저장소를 복제할 때 자동으로 활성화되지 않는다. 저장소마다 한 번 설정한다. 기존 `core.hooksPath`나 `.git/hooks/pre-push`를 사용한다면 기존 훅에 이 검사 호출을 합친다.

```sh
# 이 저장소의 공개된 훅 폴더를 사용한다. 전역 Git 설정은 바꾸지 않는다.
git config --local core.hooksPath .githooks
```

이후 `git push`는 전송할 커밋의 문서 상태를 검사한다. 작업트리에만 고친 문서가 있어도 커밋에 빠졌다면 실패한다. 새 브랜치와 여러 참조의 push도 검사하고, 브랜치 삭제에는 문서 검사를 실행하지 않는다. GitHub Actions의 `docs` 작업은 PR·push에서 같은 검사를 수행한다. 로컬 훅을 우회하면 원격 전송 자체는 가능하므로, 서버에서 병합을 막으려면 저장소 규칙에서 `docs / docs` 검사를 필수로 설정한다.

문서 검사 스크립트는 각 저장소에 포함되어 있어 다른 SENTINEL 저장소를 복제할 필요가 없다. 공통 구현 원본은 [SENTINEL의 docs_lint.py](https://github.com/hwain-ai/SENTINEL/blob/main/scripts/docs_lint.py)이며, 공통 검사 동작을 바꿀 때는 동반 저장소의 사본도 함께 갱신한다. 실행 방법이나 규칙을 바꾸면 이 문서도 고친다.

CI는 일반 브랜치 push에서 이전 원격 커밋과 제출 커밋을 비교한다. PR은 대상 브랜치와의 공통 조상, 새 브랜치는 기본 브랜치와의 공통 조상부터 비교하므로 다른 브랜치의 변경을 이번 문서 수정으로 잘못 세지 않는다. 비교할 이력이 없으면 실패하며, 기본 브랜치를 처음 만드는 경우에만 전체 파일을 새 문서와 대조한다. 브랜치 삭제와 태그 push는 이 문서 CI의 대상이 아니다.

검사 구현은 문서 목록·연결 규칙 검증, 링크 확인, 변경분 비교, 실행 환경별 기준 선택을 나누어 처리한다. 공통 스크립트를 수정할 때는 문서 검사 동작 시험과 각 저장소의 자체 품질 기준을 함께 확인한다.

통합 CI는 Linux에서 전체 실행기 시험을, macOS Intel·Apple Silicon에서 지원 명령과 설치 충돌 시험을 실행한다. `scripts/verify_native.py`는 승인된 언어 소스로 `setup`·`plan`·`version`을 실행한 뒤 파일·함수 검사, 약한 테스트의 기준 미달, 전체 재검사까지 확인한다. 설치 상태 확인 결과의 `command`도 `version`이어야 한다. 테스트의 경로 깊이와 Python 시작 환경은 운영체제 차이를 반영하며 검사 기준은 동일하다. 실험용 Go·OCI 경로는 Linux 전용이다.

`start`의 설치·초기 설정과 `sentinel`의 검사·수정 지침을 구분한다. 공통 설치 절차는 하나의 참고 문서를 사용하며, `start-context` 규칙은 초기 설정이나 기본 기준이 바뀔 때 start 지침도 확인하도록 연결한다.

기본 `sentinel`·`fix`는 수정까지, `check`는 측정만 수행한다. 공개 스킬의 역할이 바뀌면 `skill-usage` 규칙에 따라 README를 함께 갱신한다. 저자가 공개한 실험 자료는 `docs/evidence/`에 원문을 보존하고, 설명 문서에 출처 페이지와 관측값을 적는다. PDF를 교체하면 실험 설명과 README도 확인한다.
